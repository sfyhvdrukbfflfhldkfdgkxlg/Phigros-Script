# Phigros Script data1.0.9-r10

修复“会话停止：索引 -1 超出长度为 26 的范围”，清理遗留时间表逻辑和重复入口，并核对全部 1057 张脚本的难度与数据。

包名 `io.github.phiscript`，versionCode 34，界面 data1.0.9-r10，与 R9 使用相同证书，可覆盖安装。

## 越界修复

用用户提供的 `Desultory_Signals_AT.pez` 在 R9 实际代码中复现相同异常：`UnifiedGesturePlanner.assign` 内 `live.get(-1)`，列表长度为 26。交叉连键被拒绝后，程序仍拿 `-1` 继续读取触点。

修复为立即结束当前音符的交叉比较，由调用方为该音符建立独立触点。没有跳过音符或吞掉异常。最终 APK 规划器只改变这一条跳转，其他方法和指令保持一致。

3、26、64、128 个已有触点的交叉/普通连接、两种桥接条件及音符完整性共 24 项断言通过。上传 PEZ 含 24 条判定线、2026 个音符、160 个噪域，最终 APK 代码通过解码、解析和演奏手势预生成。PEZ SHA-256：`7f63e3dec8e45321a668928b2c981244bd015cade931e551126b10fd60491af1`。

## 时间表和校准检查

R9 确实还在 APK 扫描和谱面读取后保存时间表，但没有把它用于实际重试起点。R10 删除这些调用和工具入口，并检查最终 DEX。

| 项目 | R10 状态 |
| --- | --- |
| APK 导入时批量生成时间表 | 已移除 |
| 演奏前保存时间表 | 已移除 |
| 首键时间 / 导入时间表入口 | 已删除 |
| ChartTimingIndex、FirstNoteBrowser 及内部类 | 无定义、无引用 |
| PhigrosStartGate、PhigrosControls、PhigrosHudProbe、SharedPhiraControls | 无定义、无引用 |
| 实际读谱时钟 | 两游戏共用 PhiraSessionEngine → PhiraRestartClock |
| 偏移 | 谱面、游戏全局、触控偏移按 Phira 流程计入一次 |
| 重试延迟编辑 | 只保留“Phigros / Phira · 重试校准” |

“识别区域与设备设置”保留识别区域、视口、暂停区域及全局/触控偏移，删除重复的重试延迟输入框。纯视觉模式保留截图补偿。

源码中的 PhigrosRetryClock 是兼容辅助类及共享设置键定义，不在会话调用链中；它也委托 PhiraRestartClock，没有独立时间表校准。旧时间表文件不再被新读谱流程读取，更新不清除已导入谱面。

## 重复入口

- 已安装 APK 的 Root 导入和普通/Shizuku 扫描合并为“导入已安装游戏 APK”，按当前触控方式使用对应读取路径；文件选择导入保留。
- Shizuku/无障碍诊断统一放在“权限与触控”。
- Phigros 手选统一从首页模式选择和“开始打谱”进入。
- 删除时间表工具，重试延迟保留一处编辑。
