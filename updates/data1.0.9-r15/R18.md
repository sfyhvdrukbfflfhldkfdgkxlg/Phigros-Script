# Phigros Script · data1.0.9-r18

基于 R17，versionCode 42。包名和签名继续与 R15 / R16 / R17 一致。

## 本机谱面删除

首页曲库中打开「删除本机导入谱面 · Phira / Pro」，选择曲名和难度，核对后确认删除。

删除的是本应用保存的谱面副本及选中状态，原始 PEZ / ZIP、Phira / Phira Pro 自己的谱库、Phigros 隔离存储均保留。识别、演奏、触控或导入进行中禁止删除；确认窗口打开后谱库发生变化时也会拒绝旧操作。最后一张删除后不会被索引备份恢复。

## 回放相关改进

针对提供的 Phira Pro v5 回放检查真实触控生命周期与判定分布，补充真实计算耗时的回归。独立新蓝键在无连续触点、不会妨碍下一按键且窗口内无噪域时，减少重复计算并保持正常按下时长。延迟统计改在计算完成、实际提交前读取。

含噪域和连续轨迹仍按其原本时序检查；不会为了保留一次点击而任意延长经过动态噪域的触点。回放的整体早晚偏差需要结合设备重新校准，不能仅凭一次记录推断所有漏判的原因。

噪域的累计缩放、旋转变换改为关键帧前缀，重复几何查询使用有界的精确时间缓存。固定视口下查询不再反复从首个关键帧累计；不做时间近似，也不改变反转区域规则。

演奏期间的噪域选点搜索加入时间预算：搜索耗时超限时先走原有抬指与下次重试，避免为了搜索安全点长时间占住旧触点。预规划阶段可继续完成完整搜索。

此次回放中，已命中 Tap 的中位误差约 −44.7ms、Hold 约 −43.3ms。可在「重试校准 → Phira / Phira Pro」将当前起始延迟增加约 40ms 后重录比较；这是针对这次记录的校准试值，不是通用默认值，也无法单独解决全部 Miss。程序不会静默改写原有校准。

源码附 `patch/tools/analyze_ppr.py`，可只读分析 v5 回放，需要 Python 的 `zstandard`。未将用户的原始回放、玩家标识或游戏本地路径放入源码包。

## 构建和回归

工具布局沿用 R17，仍使用官方签名 R15 APK 作为校验基线：

```sh
python patch/build_r18.py path/to/PhigrosScript_data1.0.9-r15.apk --key path/to/testkey.pk8 --cert path/to/testkey.x509.pem
python patch/tests/run_r18.py deliverables/PhigrosScript_data1.0.9-r18.apk
```

回归从最终签名 APK 提取代码，覆盖谱面删除与重启恢复、实际耗时下的触控、噪域导入、前台识别、课题流程和录屏。主机模型与回放分析不能替代更新后的真机重新演奏验证。
